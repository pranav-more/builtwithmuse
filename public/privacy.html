What this site collects, and what it never does.

Need a code?

The pool hands out community invite codes for free. Take one, redeem it, then add yours.

Get a code from the pool

Built with Muse is a small community site with one job: hand you a working Muse invite code and let you add yours afterwards. This page lists everything the site records, why it records it, and what it never does. It is written in plain language on purpose.

What we collect

  • Codes you add. The invite code, the optional invite link, and the country, region and city that our host attaches to the request. Location is kept so moderators can spot fake or duplicated submissions.
  • Claims. When you take a code we store a random device id from a cookie, a salted hash of your IP address, and the same location fields. Together they enforce one code per person and the rate limits that keep scrapers out. The raw IP address is never stored.
  • Feedback on a code. Pressing I redeemed it or Not working records that action against the code and your device id, so verified codes can be shown as verified and broken ones can be retired.
  • Waitlist. Your email address and the country you choose, plus the location fields above.
  • Analytics. Google Analytics, Microsoft Clarity and Vercel Web Analytics run on every page. They record page views, device and browser type, rough location and, in the case of Clarity, anonymised session replays. Each uses its own cookies under its own policy.

Why we collect it

  • To give each person one code and stop anyone from draining the pool.
  • To retire codes that do not work and show which ones have been verified.
  • To email waitlist members once, when Muse reaches their country, with a fresh invite code.
  • To see which pages help people and which do not.

What we never do

  • We do not sell or rent any of this data, and we do not share it with advertisers or data brokers.
  • Waitlist emails are used for that one launch email and nothing else. There is no newsletter.
  • There is no account and no password here. We never ask for your Meta or Muse login, and nobody legitimate will ask for it in exchange for a code.
  • Codes are never published in full. The public pool shows a masked version, and the full code is shown only to the person who claimed it.

Cookies

  • bwm_d: a random, signed device id that lasts one year. It is HttpOnly and it is what makes one code per person possible without a sign in.
  • bwm_admin: set only for the moderators who sign in to the admin dashboard with Google.
  • Analytics cookies set by Google Analytics, Microsoft Clarity and Vercel Web Analytics.

Where the data lives

The site runs on Vercel and the database is Postgres on Supabase in the US West region. The moderators who run this site can see submitted codes, claim records, reports and the waitlist through a dashboard that requires a Google sign in from an allowed address.

Retention and removal

Records are kept for as long as the pool runs, because they are what keeps it fair. If you want your code removed from the pool, your email taken off the waitlist, or your claim records deleted, email the address below with the code or email in question and it will be done within a few days.
